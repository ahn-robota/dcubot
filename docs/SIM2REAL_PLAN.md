# 실물 첫 보행(sim2real) 절차

200M 장기 학습의 최종 정책(`checkpoints/long14/2026_11_06_000746_7864320.onnx`, 실습실 PC에만 있음)을 실물에 올리는 순서. 단계마다 확인 항목을 통과해야 다음 단계로 간다. 하드웨어 값(서보 ID·방향, IMU 변환)은 `hardware/bringup` 브랜치의 `docs/HARDWARE_SETUP.md`, `hardware/dcubot_hw_config.json`.

## 정책이 기대하는 실행 조건

| 항목 | 값 | 근거 |
|---|---|---|
| 제어 주기 | 50 Hz (`ctrl_dt` 0.02) | `playground/dcubot/joystick.py` |
| 목표각 | 기본자세 + 행동 × 0.25 rad, 변화는 5.24 rad/s로 제한 | `action_scale`, `max_motor_velocity` |
| 관측 | 94개: 자이로, 가속도, 명령(3+머리 3), 관절 각도·속도, 이전 행동 3개, 목표각, 발 접촉 2개, 걸음 위상(cos, sin) | `mujoco_infer.py`의 `get_obs`와 같아야 함 |
| 좌우 대칭 추론 | 필수: `SymmetricPolicy(pre_tanh=True)` | `--symmetric_policy`로 학습 |
| 견디는 지연 | 행동·IMU 각각 0~3스텝(최대 60 ms) | `noise_config` |
| 서보 | P 32, kp 17.8 / 힘 3.35 N·m(7.4 V 기준) | `CHANGES_FROM_ORIGINAL.md` 최종 URDF 절 |

## 0. 디지털 트윈에서 확인 (실물은 움직이지 않음)

- [ ] 관측 94개의 부호·크기가 시뮬레이션과 같다: 로봇을 손으로 앞·옆으로 기울이고 관절을 움직이면서 `mujoco_infer.py`의 `get_obs` 값과 비교. 대상은 IMU 자이로·가속도(축 변환 후), 관절 각도·속도(부호 반전 3개 포함), 발 접촉
- [ ] 발 스위치: 밟으면 1, 떼면 0
- [ ] 루프가 50 Hz를 유지하고, 센서 읽기부터 명령 전송까지 60 ms 안쪽
- [ ] 정책 출력(목표각)을 실물에 보내지 않고 트윈 화면에만 표시해서, 정지 명령일 때 기본자세 근처에 머무는지

## 1. 매달아 놓고 실행 (발이 바닥에 닿지 않게)

- [ ] 정지 명령: 관절이 기본자세 근처에서 떨림 없이 유지
- [ ] 걷기 명령: 다리가 번갈아 움직임
- 떨리면 지연 또는 kp 문제. 바닥에 내리기 전에 해결

## 2. 바닥에 세우기 (손이나 끈으로 받쳐서)

- [ ] 정지 명령으로 서 있음
- 앞으로 쏠리면 무게중심이 모델과 다른 것: 전체 무게(모델 2.075 kg), 라즈베리파이·전자부품 위치를 재서 URDF를 고치고, 실습실 PC에서 최종 정책을 이어서 학습

## 3. 제자리 걸음 → 천천히 전진 → 나머지 방향

- [ ] 0.1 m/s 전진부터. ±0.05 m/s 같은 아주 느린 명령은 시뮬레이션에서도 서 있음
- [ ] 옆걸음, 회전, 후진 순서로

## 문제가 생길 수 있는 곳

| 항목 | 이유 | 대처 |
|---|---|---|
| 무게중심 | 전원 없이 세웠을 때 앞으로 넘어졌음 | 2단계에서 확인, URDF 수정 후 재학습 |
| 배터리 전압 | 서보 힘이 7.4 V 기준이라 전압이 떨어지면 약해짐 | 완충 상태에서 시험 |
| 바닥 | 학습한 마찰 0.4~1.0 | 미끄러운 바닥 피하기 |
| 밀림 | 시뮬레이션에서도 세게 밀면 약 33%가 8초 안에 넘어짐 | 처음엔 받쳐 주면서 |
